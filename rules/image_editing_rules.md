# 画像編集・修正の運用ルール

更新日：2026-11-12（軽微差分許容・実行前確認の改訂）  
基準：開始パック v1.0 の画像編集ルール

## 1. 基本方針
- 指定された修正箇所以外は変更しない。
- 元画像の構図・色彩・質感・細部を維持する。
- 修正指示を不必要に拡大解釈しない。
- 修正範囲が曖昧な場合は、勝手に広範囲を変更しない。
- 参照画像は指定された特徴の参照に限り、指定外の特徴を無断で移植しない。

## 2. 標準編集方法：部分合成方式
既存画像の修正では「部分合成方式」を標準とする。**画像全体の再生成を局所修正の完成画像として採用しない。**

### 2.1 変更範囲の定義
変更対象は次の2種類として定義する。
- **要素単位変更**：指定された要素だけを変更する。
- **領域単位変更**：指定されたパネル・枠・領域の内部全体を変更対象とする。

領域単位変更では、領域内は目的に応じて全面的に描き直し・再構成してよい。
ただし、**指定領域の外側は原則として見た目・デザインを維持する。** 自然な継ぎ目に必要な軽微な隣接変更のみ、範囲と理由を記録して許容する。
「変更しない部分」という指示は、原則として変更対象領域の外側を指す。

1. 原本と参照画像を区別し、修正対象を特定する。
2. 編集許可領域と編集禁止領域を明確にする。
3. 必要な場合だけ局所的な修正案を生成する。
4. 必要な修正部分だけを切り出す。
5. **原本を土台に**該当箇所だけを合成する。
6. 合成境界のみを必要最小限になじませる。
7. 許可範囲外の差分と修正範囲内の見た目を別々に検証し、意図しない変更を不合格にする。

### 2.2 新規作画を伴う領域差し替え
- 特定の顔画像をもとに詳細パネルを作る場合、その顔に描かれている対象パーツを**一次原本**とする。
- 目の詳細なら、元顔の目の形・横縦比・目尻/目頭・上/下まつ毛・虹彩径・瞳孔・ハイライト・まぶた線を維持して資料化する。
- 「切れ長」「アーモンド型」等の抽象語は補助説明に留め、元画像と異なる新規デザインの根拠にしない。
- 「詳細」は写実的に描くことではなく、**同じアニメ/イラストデザインを拡大・分解して構造が分かるようにすること**。

- 目の詳細パネル等を新たに描き直す場合、**パネル単体だけを生成**し、シート全体を生成対象にしない。
- 対象パネルは既存キャラクターデザインの構造を分かりやすく説明する図とし、写実化や別人化をしない。
- 新規パネルはまず WORKING として単体で提示し、承認前は原本へ合成しない。
- 承認後に非生成処理で指定領域を原本へ合成し、領域外の差分を検出・目視確認する。継ぎ目の軽微な差分は範囲・理由を明示して許容する。ユーザーが「完全維持」を指定した場合は変更禁止領域のRGBA差分ゼロを検証する。
- 全体画像の再生成は不可。失敗した候補を完成品や正本として扱わない。

## 3. 維持対象と許容差
- **原則：指定外のデザイン・見た目・絵柄・全体の雰囲気を維持する。** 画素値の完全一致は、通常の局所修正では必須としない。
- 修正箇所の継ぎ目や周辺の自然な接続に必要な軽微な差分は許容する。どの範囲をなぜ変更したかを記録し、提出時に示す。
- 顔立ち、髪型、体型、衣装、構図、配色、絵柄、全体の雰囲気など、変更指示のない重要要素の再設計は引き続き禁止。
- 許可範囲外に意図しない変更が見つかった場合、ユーザー確認なしに採用しない。
- **「完全維持」「画素を変えない」等の明示指定がある場合に限り**、事前に定義した変更禁止領域のRGBA画素差分ゼロを必須条件とする。
- 「画素差分ゼロ」を緩和しても、**局所修正を画像全体の再生成で代用する禁止事項は緩和しない**。AI出力全体をそのまま局所修正の完成画像として提出しない。
- 差分検証できない場合は「差分ゼロ」「完全維持」と報告しない。実施できない工程は説明して停止し、無断で別方式へ変更しない。

## 4. 検証
### 画素
- 原本と完成画像のピクセル寸法が一致しているか。
- 許可領域外の差分がどこにどれだけあるか。透過画像はアルファも比較。完全維持指定時は変更禁止領域のRGBA差分ゼロか。
- 許可領域外に色調整、にじみ、輪郭変化がないか。
- 差分範囲と処理範囲が一致するか。

### 目視
- 修正対象が指示どおりか。
- 境界に欠け・浮き・重複・切断・継ぎ目がないか。
- 手指、手首、腕、足、輪郭、身体比率が自然か。
- 文字、数値、配色見本、装飾が意図せず変わっていないか。

通常修正では、許可範囲外の意図しない変化がないことと、修正領域の自然さを別々に判定する。完全維持指定時は画素差分ゼロも別途必須。

## 5. 出力
- 原則として元画像と同じピクセル寸法。
- 完成画像はPNGを基本とする。
- 原本を上書きせず、修正版を別ファイルとして保存。
- ファイル保存とプロジェクト登録は別工程。
- 実施していない工程を「完了」と報告しない。

## 6. 切り出し・透過・資料
- 元イラストを使えるなら再描画より直接切り出しを優先。
- 三面図等は縦横比を維持し、不必要な個別変形をしない。
- 手足、髪先、小物が切れない余白を確保。
- 透過で淡い輪郭が欠けるなら無理に完成扱いしない。
- 複数イラスト、文字、パレットを含む資料は各要素の編集可否を分ける。
- 拡大縮小、再描画、色変換した部分を「元画素完全維持」と報告しない。

## 7. 反復と不合格
- 明確な破綻がある候補を完成品として提出しない。
- 原則として指定原本からやり直し、劣化中間画像を無条件に次の原本にしない。
- 小領域の継ぎはぎで不自然になる場合、解剖学的に一体の修正範囲を相談する。
- 合格できない場合は無理に完成とせず、問題と代替案を示す。

## 8. 今後の運用
- ユーザーが毎回「部分合成方式」と指定する必要はない。
- より適切な方法が見つかった場合は、既存ルールを無断変更せず改訂案を提示する。
- 実行できない工程がある場合は完了を装わない。

## 9. 提出前チェック
- [ ] 原本と参照画像を正しく区別した
- [ ] 編集許可領域と編集禁止領域を特定した
- [ ] 編集禁止領域を生成結果で置換していない
- [ ] 許可領域外の差分を確認し、軽微な継ぎ目変更の範囲・理由を記録した。完全維持指定ならRGBA画素差分ゼロを検証した
- [ ] 修正領域の自然さ、輪郭、接続、文字・配色を目視確認した
- [ ] 画像サイズ、形式、透過情報を確認した
- [ ] 実施工程、未検証事項、残る問題を正確に報告した

**最重要原則：変更を指示されていないデザイン要素は、生成AIに維持を期待するのではなく、原本を土台に技術的に保護する。必要な継ぎ目の軽微な差分のみ、理由と範囲を明示して許容する。**


## 10. 生成AIの使用判定
- 新規作画が必要な場合のみ生成AIを使う。
- 余白、配置、文字、切り出し、合成、キャンバス拡張など、既存内容を保持できる処理は生成AIを使わない。
- 既存画像の維持が主目的の作業では、画像全体の再生成を禁止する。
- 作業前に「生成AIが必要か」を判定し、不必要なら非生成処理へ切り替える。
- 生成時の正式な人物デザイン基準は、正本・APPROVED_REFERENCEに限定する。ユーザーが限定採用し、manifestに用途・scopeが明記されたWORKINGは、その範囲でのみ補助的な作業参照に使用できる。TRIALは比較・判断補助に限り、REJECTEDは参照禁止、ARCHIVE・SUPERSEDEDは通常制作の参照に使用しない。

## 11. 作業開始前の参照・実行方式チェック
- 毎回、GitHub `main` の `rules/current_rules.md` と本ファイルを**実際に取得して読む**。リンクの記載や過去の読了は取得の代わりにならない。キャラクターの正本・manifest・ToDoも必要な範囲で取得する。
- ツールを呼ぶ前に「今回の原本・変更対象・維持対象・許可する境界調整・使用する方式・検証方法」を確認する。**全身生成しかできない状態で局所修正を依頼しない。**
- 取得できない、あるいは適合する編集方法が使えない場合は、できないと説明して該当作業を停止する。無断で全体生成へ切り替えない。
- 実施した参照・検証と未実施の項目を区別して報告する。
